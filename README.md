# Student Record Management System

Cloud Computing Assignment 1: a Flask web app that manages student records in a relational database.

**Live demo:** http://13.232.187.76/ (temporary link, available while the project is under review)

## Architecture
Browser -> Nginx (port 80) -> Gunicorn -> Flask app (EC2, Ubuntu 26.04) -> Amazon RDS MySQL 8.4 (private, port 3306)

- **VM:** AWS EC2 t3.micro, ap-south-1 (Mumbai)
- **Database:** Amazon RDS MySQL 8.4, db.t4g.micro, not publicly accessible; only the EC2 security group can connect
- **Stack:** Python Flask, PyMySQL, Gunicorn, Nginx

## Features
- Dashboard: totals, enrollments per course, students with no enrollments
- Students: add, view, update, delete, search by ID / name / email
- Courses: add, view, delete
- Enrollments: enrol a student in a course, edit grade, remove
- Reports (with CSV download): courses taken by a student (by Student ID); students enrolled in a course
- Deletion protection: a student or course with enrollments cannot be deleted; a clear warning is shown, and the database enforces it too (`ON DELETE RESTRICT`)

## Tests
`tests/` holds the automated checks used during development (about 150 assertions covering login, roles, CSRF,
lockout, audit logging, reports, deletion protection, AI insights with a mock AI server, the interface and the demo-data
script). They run against a **local** MySQL/MariaDB test database only (host is hard-coded to 127.0.0.1). See `tests/README.md`.

## Demo data and scripts
- `python seed_demo.py` loads fictional demo data (12 students, up to 12 courses, ~46 enrollments). Safe to run twice; it only adds what is missing, and writes one audit entry.
- `python generate_insights.py` pre-generates AI insights for every course without one (respects the daily AI limit).
- `python manage.py create-user NAME --role admin|viewer` creates login accounts.

## Interface
Navy / cream / coral theme (colours are variables at the top of `static/style.css`), active-page highlight, role badge, account menu, dashboard with per-course bars, colour-coded audit actions, responsive layout.

## AI course insights
Each course has an **AI Insights** page: a short overview (what it covers, key topics, skills and careers, relevance today, next courses) generated by a free AI API (Google Gemini by default, with Google Search grounding when the free tier allows it; Groq as an alternative). Only the course name is sent, never student data. Answers are cached in `course_insights` (30 days), limited per user per hour and per day to protect the free quota, and every request is written to the audit log. The API key lives only in `.env`.

## Security
- Login with hashed passwords (scrypt via Werkzeug); no default or hard-coded credentials; first admin is created from the command line (`manage.py`)
- Roles: `admin` (change data, manage users, view audit log) and `viewer` (read-only, reports)
- CSRF protection on every form, HttpOnly + SameSite session cookies, 2-hour sessions, security headers
- Brute-force protection: 5 failed sign-ins (per user or IP) lock sign-in for 10 minutes
- Sessions are re-validated against the database on every request (deleting a user ends their session)
- Network: RDS is private; the EC2 security group is restricted to approved IPs
- Secrets live in `.env` (git-ignored); the app refuses to start with a weak `SECRET_KEY`

## Audit logging
Every create / update / delete, sign-in, failed sign-in, lockout and sign-out is written to `audit_log` with user, time (UTC), IP, record and before/after values. Admins can filter and export it at `/audit`.

## Database
`schema.sql` creates `students`, `courses` and `enrollments` (3NF). Enrollments resolves the many-to-many relationship with foreign keys, a unique (student, course) pair, and ON DELETE CASCADE.

## Upgrading an existing database
Run once, in order:
```
mysql -h <rds-endpoint> -u admin -p < migrations/01_restrict_deletes.sql
mysql -h <rds-endpoint> -u admin -p < migrations/02_users_and_audit.sql
python manage.py create-user <your-username> --role admin
mysql -h <rds-endpoint> -u admin -p < migrations/03_ai_insights.sql
```

## Deployment steps
1. Launch an EC2 Ubuntu instance; security group allows SSH (22, your IP) and HTTP (80).
2. Create an RDS MySQL instance (initial DB name `student_db`, public access No) and connect it to the EC2 instance.
3. On the VM: `sudo apt update && sudo apt install -y nginx python3-venv python3-pip mysql-client unzip`
4. Load the schema: `mysql -h <rds-endpoint> -u admin -p < schema.sql`
5. Copy this project to `/home/ubuntu/student-app`, then:
   ```
   python3 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   cp .env.example .env     # then edit .env with the real DB password
   ```
6. Run as a service: copy `deploy/studentapp.service` to `/etc/systemd/system/`, then `sudo systemctl daemon-reload && sudo systemctl enable --now studentapp`
7. Nginx: remove the default site, copy `deploy/nginx-studentapp.conf` to `/etc/nginx/sites-available/studentapp`, symlink it into `sites-enabled`, run `sudo nginx -t`, then `sudo systemctl restart nginx`.

Credentials live in `.env`, which is excluded from the repository.
